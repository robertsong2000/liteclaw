# [Vehicle Manual] Manual QA Assistant V1 Prototype (liteclaw manual-rag)

## 背景

车书项目需要验证"本地 LLM + 车主手册 RAG"的可行性：通用大模型凭记忆回答车辆问题会编造保养周期、胎压数值等关键信息，存在安全风险。需要基于 liteclaw（本地 AI 编程助手，Web 对话 + Agent Loop + Skill 系统）搭建车书助手第一版原型，跑通"手册入库 → 混合检索 → 受控问答 → 边界评测"全链路，并选出本地（Jetson）环境下性价比最优的模型档位。

样例车型：Renault 5 E-Tech Electric 2025（纯电）车主手册。

## 目标

为车主提供基于官方车主手册的可信问答能力：任何车辆问题必须先检索手册，回答只来自检索原文并附页码引用，检索不到就明确回答"手册中没有相关内容"，杜绝凭记忆编造。

## MVP 范围

### 场景 1：手册知识库与混合检索（skill: manual-rag）

- 手册解析入库：PDF → 354 个 chunk，字段含 PDF 页码区间 / 章节 / chunk_id / safety_level
- 混合检索：BM25 + 向量（bge-m3 embedding）双路召回，RRF（k=60）融合排序
- 单入口脚本 `rag.py`：
  - `rag.py "<问题>"` 返回 JSON 命中（rank / source / section / safety_level / text）
  - `rag.py --ingest` 重建索引；内置向量自检与重试

### 场景 2：车书问答（liteclaw Web 对话）

- 强制检索纪律：车辆问题（功能、按键、警告灯、充电、保养）必须先 `skill_run("manual-rag")`，禁止凭记忆作答；非车辆问题礼貌拒绝并拉回车书场景
- 回答规范：只按检索原文作答，数字 / 警告措辞原样引用；结尾附"参考来源：用户手册 p.<页码>"（最多 4 条）；未经检索严禁输出页码或"参考来源"字样
- 拒答规范：检索未覆盖 → 明确回答"手册中没有相关内容"
- 中文回复，口语化、结论先行，普通问题 300 字以内，安全警告原样保留
- Web UI 建议问题 chips：基础组 + 边界测试组（悬停显示预期答案，点击即可对照验收）

### 场景 3：边界评测与模型选型

- 14 题边界测试集：6 基础 + 1 转述 + 4 命中 + 3 拒答（纯电车必然没有的机油 / 汽油滤芯 / 油箱盖问题）
- 判定标准：命中题"有页码且内容对得上 = 过"；拒答题"答没找到 = 过"；任何题跳过检索直接作答 = 挂
- 模型对比（qwen3:8b / qwen3:30b-a3b / nothink 变体）：RAG 调用率、引用率、拒答纪律、平均耗时
- 选型结论：默认 qwen3:30b-a3b-nothink（与深度思考版逐题判定完全一致，耗时 -63%）；1~2B 模型工具调用纪律不达标，不适用于车书场景

## 技术备注（已知坑，建议放 Jira comment）

- 本机 Ollama 新版 `/api/embed` 返回坏向量（相关文本 cos≈0），需改用 legacy `/api/embeddings` + `num_ctx: 8192`，并对每个返回向量做有效性校验
- chunk 上限 700 字符（embedding runner 有硬性 512 token 批次限制）
- 小模型存在"幻景式工具声明"（声称已调用工具但实际没调）与"凭记忆作答 + 编造引用"的失败模式，自动判分需人工复核兜底
